# 星钥塔罗 UI 焕新验收标准

## 0. 本轮范围与成功标准

- 本文件基于 `deliverables/stitch_to_arkui_harmony_refresh_plan.md`、`AGENTS.md`、现有 `Theme.ets`、`MoonlightLayer.ets`、`StarBackground.ets`、`CompanionBottomNav.ets`、`MainFramePage.ets` 整理。
- 本文件只定义 UI 焕新验收标准，不要求也不允许迁移 Stitch 的 React / Tailwind / motion / lucide-react / Gemini / fetch / localStorage 实现。
- 成功标准：后续每个 Codex 窗口都能用本文件判断页面是否符合“星钥塔罗焕然一新”的视觉目标，并知道哪些代码、逻辑和文案边界不可触碰。

## 1. 总体视觉关键词

UI 焕新必须同时满足以下关键词：

- 深夜
- 月光
- 星河
- 湖面
- 星钥
- 塔罗牌
- 安静陪伴
- 克制
- 高级
- 低刺激
- 非博彩
- 非乙游
- 非抽卡手游

整体判断标准：

- 第一眼应是深夜蓝黑、月光微亮、星河稀疏、卡牌可阅读。
- 氛围应安静、温柔、被接住，不刺激用户反复点击或追求奖励反馈。
- 塔罗体验应像翻阅星钥之书，而不是抽卡、开奖、转盘或恋爱互动。

## 2. 全局色彩标准

- 主背景应保持深夜蓝黑，优先复用 `Theme.V2_BG_BASE`、`Theme.V2A_BG_BASE`、`Theme.V2B_BG_BASE`、`Theme.V2C_BG_BASE`。
- 金色只用于标题、细线、选中态、少量 CTA、边框微光，不得铺成大面积背景。
- 正文以月光白为主，优先使用 `V2_TEXT_PRIMARY` 或对应 A/B/C 的 `TEXT_PRIMARY`。
- 辅助文字使用星灰，优先使用 `V2_TEXT_SECONDARY`、`V2A_TEXT_SECONDARY`、`V2B_TEXT_SECONDARY`、`V2C_TEXT_SECONDARY`。
- 边框应是低透明星轨线、书脊线或月光细线，不应形成强描边。
- 禁止霓虹紫、大面积金色、强红色、廉价渐变、强对比彩虹色。
- 危险或提示色只能低饱和、小面积使用，不得破坏深夜低刺激基调。

## 3. A / B / C 三套视觉验收标准

### A「星图档案」

适用页面：

- 我的页
- 星历
- 历史记录
- 头像裁剪
- 关于 / 协议 / 使用说明类页面

验收标准：

- 视觉关键词是克制、档案感、记录感、星轨细线、信息层级清晰。
- 页面应像“被记住的记录”，而不是功能堆叠面板。
- 卡片信息密度可以高于 B/C，但必须有清楚的标题、时间、状态、分割线。
- 星轨线、日期、历史条目、等级信息应保持低调，不做强光和强动画。
- 我的页和星历不得修改头像 / 昵称持久化、星历点亮规则、星钥等级阈值。

### B「月湖映心」

适用页面：

- 星澜聊天入口
- 星澜聊天页
- 星澜语录
- 情绪星

验收标准：

- 视觉关键词是月光、湖面、柔和遮罩、低刺激、被接住。
- 可使用 `MoonlightLayer` 的月光呼吸，但强度必须轻，不能强闪。
- 如使用人物图，必须暗化、渐隐、降低饱和度，并融入深夜背景。
- 星澜应是安静陪伴者，不是全屏恋爱立绘、偶像主视觉或暧昧对象。
- 聊天页不得修改聊天核心管线、SafetyGuard、分析路由与回复组合逻辑。

### C「星钥之书」

适用页面：

- 占卜中心
- 单牌
- 圣三角
- 关系探索
- 旋转牌轮
- 卡牌总览
- 卡牌详情
- 结果页
- 分享卡

验收标准：

- 视觉关键词是书页感、翻阅感、烫金细线、卡牌阅读层级。
- 卡牌结果应优先呈现“标题 / 卡牌 / 金句 / 分段解读 / 行动按钮”的阅读秩序。
- 金色只作为烫金细线、标题或关键句点缀，不能做开奖式大光效。
- 牌轮应保留手势与惯性体验，但视觉上必须避免赌场转盘和抽卡手游感。
- 不得修改抽牌算法、牌阵含义、78 张卡牌数据、历史结构、分享卡核心逻辑。

## 4. 组件级验收标准

### 页面背景

- A 使用深夜档案底，允许星轨线和克制分层。
- B 使用深湖夜色、月光柔罩、轻微湖面感。
- C 使用深蓝黑旧书封壳感，允许书脊线和低透明烫金。
- 背景不能抢正文信息层级，不能强渐变、强闪光、强紫色。

### 卡片

- A 卡片偏档案纸：信息清晰、边框克制、分割线明确。
- B 卡片偏柔和湖面：圆角较大、透明度低、边界柔。
- C 卡片偏书页：更方正、书脊线或烫金细线点缀。
- 所有卡片不得堆叠过多阴影，不得像游戏奖励面板。

### 主按钮

- 只用于关键行动，例如进入、开始、确认、保存。
- 允许少量金色或金色文字，按钮面积不得造成“大面积金色”。
- 按压反馈以 `scale 0.97` 或同级轻缩放为准。
- 禁用态必须灰化并降低对比，不得仍像可点击 CTA。

### 次级按钮

- 使用透明深色底、细边框、月光白或星灰文字。
- 不抢主按钮层级。
- 返回、取消、查看详情类按钮应低刺激。

### Chip / 标签

- 用于筛选、模式、焦点选项。
- 选中态可使用小面积金色文字、边框或淡底。
- 未选中态使用星灰和低透明边框。
- 不得做高饱和色块，不得像抽卡稀有度标签。

### 页面标题

- 标题应使用月光白或小面积金色。
- B 标题温柔、留白更多；C 标题有书页 / 烫金感；A 标题克制清楚。
- 不使用夸张大字、霓虹描边或强发光。

### 正文

- 正文以月光白和星灰为主。
- 行高必须保证长文阅读舒适。
- 关系探索相关正文必须聚焦用户自己的感受、期待、害怕、边界和自我照顾。
- 不得出现预测未来、承诺复合、判断对方爱不爱用户或替用户决定的表达。

### 底部导航

- 固定 5 Tab：塔罗、星澜聊天、星澜语录、卡牌总览、我的。
- 不改 Tab 数量、文案、索引、`selectedIndex/currentTab`、`onTabChange/onClick`。
- 视觉应是深色半透明胶囊、顶部细线、选中金色、未选中灰蓝。
- 必须照顾底部安全区，不遮挡内容和系统手势。

### 图标

- 图标应细线、低刺激、与深夜背景融合。
- 选中态可金色，未选中态用灰蓝 / 星灰。
- 不新增图标库，不引入 `lucide-react`。
- 不使用博彩、奖励、金币、抽卡稀有度风格图标。

### 输入框

- 输入框背景为深色半透明或低对比卡片底。
- 边框使用低透明月光 / 星轨线。
- 占位文字使用星灰，不得比正文更抢眼。
- 聚焦态可有轻微边框增亮，不做强发光。

### 聊天气泡

- 星澜气泡应柔和、低刺激、偏月湖感。
- 用户气泡可略有区分，但不能高饱和或强对比。
- 气泡允许淡入，不允许弹跳、爆闪或复杂 typing 动效。
- 聊天 UI 精修不得改聊天核心管线。

### 结果页金句卡

- 金句卡是 C 方案重点，应像书页里被轻轻标出的句子。
- 可以使用小面积烫金标题、细线、暗色卡底。
- 不得做“开奖结果”“神准提示”“命定宣判”视觉。
- 金句内容必须符合情绪陪伴与自我探索定位。

### 星历 / 历史记录卡

- 应体现 A「星图档案」：日期、记录、牌名、情绪星、状态清晰。
- 列表可扫描，详情可阅读。
- 点亮状态应克制，不得金币爆炸或奖励动效。
- 不得修改历史记录结构、星历点亮规则、等级阈值。

## 5. 动效验收标准

允许：

- 月光呼吸
- 星点慢漂
- 卡片轻微淡入
- 按钮 scale 0.97
- 选中牌轻微聚焦
- 气泡淡入

禁止：

- 强闪光
- 粒子爆炸
- 金币爆炸
- 高频闪烁
- 复杂 3D
- 抽卡手游动效
- 赌场转盘感
- 持续消耗性能的重动画

动效判断标准：

- 动效应帮助用户理解状态，而不是制造奖励刺激。
- 长页面列表不应给每个 item 加复杂入场。
- 牌轮、抽牌、结果页可以有仪式感，但必须低速、克制、可读。
- 如存在 reduced motion 需求，应优先使用静态光斑、淡入和基础按压反馈。

## 6. 图片融合标准

如果使用用户自己的图片或星澜相关图片：

- 必须暗化。
- 必须渐隐。
- 必须降低饱和度。
- 必须与深夜背景融合。
- 人物不可全屏高亮直视。
- 不允许形成乙游 / 恋爱立绘感。
- 人物只可作为氛围、轮廓或局部背景，不可压过功能和文本。
- B 页面可以使用月亮、湖面、星空局部；C 页面应以卡牌和书页为核心；A 页面应以档案和记录为核心。

## 9. 后续任务执行原则

- 每次只做一个 Task。
- 每次新窗口必须读取 `AGENTS.md`、`deliverables/stitch_to_arkui_harmony_refresh_plan.md`、`deliverables/ui_harmony_refresh_acceptance_criteria.md`。
- 每次修改前必须先读取相关文件，并搜索已有实现。
- 每次修改前必须判断目标页面属于 A / B / C 哪套视觉系统。
- 每次只处理用户指定页面或组件，不扩大范围，不顺手修无关问题。
- `MainFramePage.ets` 只能小范围改对应内联区域，不改 Tab 数量、文案、索引、路由、`currentTab`、`onTabChange`。
- `CompanionBottomNav.ets` 只能精修视觉，不重写结构。
- `XinglanChatPage.ets` 不能改聊天核心管线。
- `CardWheelDrawPage.ets` 不能改手势 / 惯性 / 算法。
- `Theme.ets` 优先复用已有 Token；只有出现明确重复和必要性时，才考虑最小新增。
- 修改后必须编译，目标为 `BUILD SUCCESSFUL`，`ERROR=0`。
- 如果只是生成报告或只读任务，可以不编译，但必须说明未编译原因。

## 10. 后续任务截图验收通用清单

每个 UI Task 完成后，截图至少检查：

- 页面是否符合所属 A / B / C 视觉系统。
